# 私密旅行空间与体验修复

2026-10-13。此版本替代原来“网站公开可读、照片桶 Public”的访问方案；不要重跑旧的公开读取策略。

## 页面变化

- 导航滚动留白由导航与状态条的实际高度决定；手机首页标题每行保持完整。
- 地图默认适配已有路线，可切换全国视图、查看全屏、点击城市进入回忆。手机嵌入地图允许纵向滚动，全屏地图支持拖动。
- 照片失败有重试入口。实况照片优先用可显示的静态封面；浏览器不支持原图时尝试动态资源。两份资源均无法读取时显示失败说明，不生成假的旅行封面。
- 日期范围与城市都相同的记录集中为一次旅行。详情保留各份文字和署名，连接同日期同目的地的计划、记录照片、手动关联的相册照片、手动关联的已完成愿望。旧记录没有作者时显示“暂未署名”，可在编辑时填写。
- 愿望可以组合关键词、主题与完成状态筛选。主题由用户选择，旧愿望保留“未分类”；完成回忆可以添加日期、感想与最多六张照片。
- 手机纪念日优先未来节点，历史折叠；首页增加最近回忆，手机省略重复的功能概览。

## 阅读与照片访问

`love_members` 保存获准使用私密空间的 Auth 用户 ID。`is_love_member()` 不接受客户端传入用户 ID，使用当前登录身份检查成员表。五张业务表的旧策略统一替换，四类可分享内容使用 `is_public`，默认值为 false；胶囊始终私密。

`storage-gateway` 保留原有上传、删除接口并增加批量 `sign-read`。成员可读取私密照片；游客只能读取公开记录、公开愿望或公开相册条目引用的照片。签名有效期十五分钟，不写入业务表或本地快照；浏览器仅暂存在内存。收回公开精选不能追回下载或缓存的副本，已发出的签名地址会在有效期结束时失效。

两个项目的 `love-photos` 都改为 Private，并增加仅针对该桶的 restrictive policy，禁止浏览器绕过网关读、写、删。网关仍使用原有服务器密钥；不把主项目 JWT 发送给第二项目。

成员缓存与草稿按账号分开；游客不渲染缓存中的旧精选，避免已收回的内容短暂重新出现。退出时清除页面里的私密内容与临时地址。旧版本未同步记录和草稿会在第一次授权成员登录时复制到该成员的恢复区，原有本地数据保留。

参考：[Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)、[Private Storage 与签名链接](https://supabase.com/docs/guides/storage/buckets/fundamentals)。

## 维护顺序

1. 核对主项目两个账号 ID、现有策略与内容数量，保存变更前配置。
2. 在主项目执行 `supabase/private-travel-space.sql`，并在同一事务中登记两个已核实的成员 ID。账号名单只保存在本机执行材料和后台，不写入公开仓库。
3. 更新主项目 `storage-gateway` 的 `core.ts` 与 `index.ts`，保留原有 Secrets 和 `verify_jwt = false` 设置。
4. 在主、第二项目分别执行 `supabase/private-media-bucket.sql`。
5. 发布页面，核对游客零条私密记录、两个成员的读取权限、旧公开照片地址拒绝访问和网关拒绝未授权签名。

SQL 只增加字段并修改访问规则，不删除旅行内容、愿望或媒体。该维护流程不开放匿名权限作为回滚；修复失败时保留私密规则。

## 验证

自动化：`node --test --experimental-strip-types tests/*.test.js`；脚本检查：`node --check script.js`、`node --check cloud-data-client.js`、`node --check travel-experience.js`、`git diff --check`。

本地浏览器检查使用虚构 API 数据，覆盖 320、390、768、1440 像素宽度、导航遮挡、旅行分组、地图切换与退出全屏、城市回忆、搜索与筛选组合、纪念日顺序。不会把这次浏览器检查当成线上登录、真实上传、Safari HEIC/MOV 解码或真机验证。

现场执行记录保存在本机 `output/playwright/dating-audit/`，该目录不发布到网站。
