# 用户名与头像设计

## 目标

登录后，页头使用用户名和圆形头像代替邮箱地址。用户可在网站内修改自己的用户名和头像，不开放公共注册，也不新增数据库表。

## 界面与交互

- 页头登录区显示圆形头像、用户名和退出按钮，不显示邮箱。
- 点击头像或用户名打开“个人资料”弹窗。
- 弹窗允许修改用户名和选择一张本地图片。
- 头像编辑区使用固定的圆形裁剪框；用户拖动图片选择区域，通过滑杆缩放，手机上同时支持双指缩放。
- 圆框外显示半透明遮罩。保存前展示裁剪结果。
- 无头像时显示爱心占位图；无用户名时显示“已登录”。

## 数据与存储

- `display_name` 和 `avatar_url` 保存在主 Supabase Auth 用户的 `user_metadata` 中。
- 裁剪结果在浏览器中生成固定尺寸的正方形压缩图片，通过现有安全网关上传到第二个 Supabase Storage 的 `love-photos/avatars/` 路径。
- 文件路径包含当前 Auth 用户 ID 和唯一后缀，避免缓存与同名冲突。
- 不新增数据库表，不修改现有业务数据或旧媒体 URL。

## 保存流程与失败处理

1. 验证用户名和所选图片。
2. 如果选择了新头像，在浏览器中裁剪和压缩，再上传新文件。
3. 调用主 Supabase Auth 更新 `user_metadata`。
4. 只有资料更新成功后才删除旧头像。
5. 上传或资料更新失败时保留旧用户名和旧头像；如新文件已上传但资料更新失败，尝试删除该未引用文件。
6. 旧头像清理失败不撤销已成功的资料更新，仅向用户显示可重试的提示。

## 安全与限制

- 只有已登录用户可以更新自己的 Auth 资料和上传头像。
- 只接受浏览器可解码的常见图片类型，并在裁剪前检查文件大小。
- 服务端上传授权仍由现有 `storage-gateway` 和登录令牌控制，不使用 `service_role` 或 secret key 于前端。
- 裁剪输出为定长正方形图片，头像展示使用圆形遮罩。

## 验证

- Auth 客户端正确读取、持久化和更新允许的 `user_metadata` 字段，不扩大会话中的敏感数据。
- 页头在未登录、无资料和已配置资料三种状态下正确显示。
- 裁剪覆盖鼠标拖动、触摸拖动、缩放边界和输出尺寸。
- 保存覆盖成功、上传失败、Auth 更新失败、新文件回收和旧头像清理失败。
- 运行现有全部测试，并在桌面端与移动端预览页面。

## 不在范围内

- 公开注册、管理员用户管理、个人主页、简介、生日或其他社交资料。
- 新建 `profiles` 数据表或修改现有数据库 schema。
- 改造网站的其他页面与业务流程。
