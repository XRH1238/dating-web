# 出游计划删除按钮与记录日期双方式输入设计

**日期：** 2026-08-05  
**状态：** 用户已确认视觉效果，等待书面规格复核

## 目标

修复两个局部体验问题：

1. 将出游计划卡片上突兀的 `×` 删除控件改为与出游记录一致的圆形垃圾桶图标。
2. 添加出游记录时，不再展示浏览器原生的 `yyyy/mm/dd` 空白提示；开始日期和结束日期都可通过日历或手动填写年月日完成。

## 范围

本次只修改：

- 出游计划列表中的删除按钮与删除确认流程；
- “写一条出游记录”表单中的开始日期和结束日期控件；
- 与上述交互直接相关的样式、脚本和自动化测试。

本次不修改：

- 添加出游计划表单的日期控件；
- 时间胶囊的解锁日期控件；
- 数据库结构、日期存储格式、地图逻辑或已有记录；
- Supabase 线上配置和 GitHub Pages。

## 出游计划删除按钮

- 计划卡右侧显示 40px 左右的圆形图标按钮。
- 使用项目已有的 `assets/icons/trash.svg`，与出游记录的删除按钮保持一致。
- 按钮具有可读的 `aria-label`，例如“删除计划：厦门三日游”。
- 悬停或键盘聚焦时使用淡粉背景和豆沙红边框，不使用长条灰色按钮。
- 点击后先打开网站现有的确认对话框，文案为“确定删除这项出游计划吗？删除后无法恢复。”
- 用户确认后才调用现有删除逻辑；取消时不产生数据变化。

## 记录日期双方式输入

### 日期摘要按钮

记录表单顶部继续并排显示“开始日期”和“结束日期”。未选择时分别显示：

- `选择开始日期`
- `选择结束日期`

选择完成后显示统一中文格式，例如 `2026年08月12日`。输入框内部不展示 `yyyy/mm/dd`。

### 日历选择

- 点击开始日期或结束日期摘要按钮，激活对应日期。
- 页面内展开自定义月历，显示当前年份、月份、星期和日期。
- 点击日期后保存到当前激活项，并高亮对应日期。
- 选择开始日期后，可自动把操作焦点切换到结束日期，但用户仍可手动切回开始日期。
- 月历提供上一月和下一月按钮。

### 手动填写

- 当前激活日期下方显示三个独立输入框：`年 / 月 / 日`。
- 年份限制为 1900–2100；月份限制为 1–12；日期必须存在于当前月份。
- 年份达到四位或月份产生有效值时，月历立即跳转到对应年月。
- 日期有效后，月历高亮对应日期，日期摘要同步更新。
- 手动填写与日历点击双向同步：通过日历选择也会反填三个输入框。

### 切换开始日期与结束日期

- 两组日期拥有独立状态。
- 切换到另一组时，三个输入框和月历恢复该组已经选择的值；尚未选择时保持自然的空白提示。
- 提交前验证结束日期不能早于开始日期，继续使用现有错误提示。

## 数据与兼容性

- 表单提交时仍通过 `MapLabelLayout.serializeDateRange(start, end)` 生成原有的 `YYYY-MM-DD/YYYY-MM-DD` 字符串。
- 旧记录、云端记录、本地缓存和列表日期格式化逻辑不变。
- 日期控件只改变输入体验，不引入新字段或数据库迁移。

## 可访问性与响应式

- 日期摘要、月份切换和日期格均为可聚焦按钮。
- 手动输入框具有明确的“年份 / 月份 / 日期”标签和数字输入模式。
- 当前激活的日期摘要使用 `aria-pressed`；当前选中日期使用 `aria-current="date"`。
- 760px 以下，开始/结束日期和年月日输入保持可读，不产生横向滚动。
- 垃圾桶图标本身为装饰，按钮的可访问名称由计划标题提供。

## 错误处理

- 无效年月日不更新日期摘要，并在手动输入区显示简短提示。
- 结束日期早于开始日期时阻止提交，不清空用户填写内容。
- 删除请求失败时保留计划卡，并显示现有云端状态提示。

## 验证标准

- 计划卡不再包含文本 `×`，而是圆形垃圾桶按钮。
- 点击计划删除按钮会先要求确认；取消不会删除。
- 空白记录日期控件不显示 `yyyy/mm/dd`。
- 手动把月份改为 `10` 后，月历标题立即显示对应年份的 10 月。
- 手动填写有效日期会高亮月历日期；点击月历会反填年月日。
- 开始和结束日期可独立切换，提交结果保持原有数据格式。
- 桌面端和窄屏布局通过浏览器检查，完整自动化测试通过。
