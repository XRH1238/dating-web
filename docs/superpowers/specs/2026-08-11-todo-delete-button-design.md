# 想做的事删除按钮设计

## 目标

为“一起想做的事”列表中的每一条事项增加明确、安全的删除能力，同时保持现有完成状态切换、筛选、分页和云端同步行为。

## 界面设计

- 每条事项继续显示现有的圆形完成状态按钮。
- 在完成状态按钮右侧增加一个始终可见的圆形垃圾桶按钮。
- 垃圾桶使用淡玫红色描边和浅色背景，与现有网站视觉风格一致。
- 两个按钮组成右侧操作区，保持固定间距，避免误触。
- 垃圾桶按钮提供包含事项名称的无障碍标签，例如“删除想做的事：一起看日落”。
- 桌面双栏和手机单栏均使用相同的操作顺序：完成按钮在左，删除按钮在右。

## 交互流程

1. 用户点击某一条事项后的垃圾桶按钮。
2. 页面显示确认提示：“确定删除这件想做的事吗？删除后无法恢复。”
3. 用户取消时，不修改页面、缓存或云端数据。
4. 用户确认时：
   - 云端可用且事项有云端 ID：先请求 Supabase 删除。
   - 云端删除成功：从页面状态移除事项并更新本地快照。
   - 云端删除失败：保留事项，显示删除失败提示，不制造刷新后重新出现的假删除状态。
   - 离线状态或事项没有云端 ID：从本地状态移除并保存本地快照。

## 筛选与分页

- “全部、未完成、已完成”三个筛选视图中的事项都可删除。
- 删除后重新计算事项总数、已完成数量和筛选结果。
- 如果删除当前页最后一条导致页数减少，自动回到新的最后一页。
- 删除操作使用事项在完整状态数组中的稳定索引，避免筛选或双栏布局下删除错误事项。

## 数据与错误处理

- 发布过程不删除任何现有愿望数据。
- 只有用户主动点击垃圾桶并确认后才执行删除。
- 不新增 Supabase 表或字段，沿用现有 `todos` 表和云端客户端的 `remove` 方法。
- 删除失败不切换事项完成状态，也不影响其他列表数据。

## 测试要求

- 渲染测试：每条事项包含完成按钮和带名称的垃圾桶按钮。
- 行为测试：删除前必须调用确认提示。
- 云端测试：成功后移除事项；失败时保留事项。
- 筛选测试：三个筛选视图中的删除索引正确。
- 分页测试：删除最后一条后页码自动收敛。
- 样式测试：操作区、圆形垃圾桶、悬停和键盘焦点状态存在，移动端不溢出。
- 回归测试：现有完整测试套件全部通过。

## 发布与验收

- 在隔离工作树中实现并验证。
- 本地测试通过后，在 Codex 内置浏览器检查实际页面。
- 用户已授权完成后直接同步 GitHub Pages。
- 发布后打开公开网站，确认删除按钮、确认提示、现有数据加载和控制台状态。
- 线上验收只打开确认提示后取消，不实际删除用户数据。
