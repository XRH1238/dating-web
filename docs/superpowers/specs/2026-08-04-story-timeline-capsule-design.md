# 出游记录时间轴与时光胶囊设计

日期：2026-08-04

## 1. 目标

本次改进聚焦“出游记录”区域：在不改变“添加计划”功能的前提下，把已有记录改造成更丰富、更有恋爱纪念感的时间轴，并在同一区域加入一颗面向未来的时光胶囊。

成功标准：

- 出游记录区域不再因内容少而显得空洞。
- 计划与记录的用途保持清晰，不让用户混淆。
- 旧记录无需重新填写即可进入新版时间轴。
- 用户可以为新记录添加心情标签和照片，但这些内容均为可选。
- 时光胶囊在解锁前不泄露正文和照片。
- 删除记录与胶囊都需要二次确认，降低误删风险。

## 2. 不在本次范围内

- 不修改“添加计划”的表单、路线编辑、交通方式或地图逻辑。
- 不新增独立的“时光胶囊”导航栏目。
- 不做地点触发解锁或浏览器定位。
- 不强制用户为旧记录补充照片、标签或新字段。
- 不在本次设计中增加多人账号、消息通知或推送提醒。

## 3. 页面结构

“出游记录”保持现有导航位置，但内容升级为“我们的故事馆”式布局。

### 3.1 区域头部

- 保留 `MEMORIES / 出游记录` 标题。
- 辅助文案改为“把一起走过的城市、当时的心情和留给未来的话，慢慢收进我们的故事里”。
- 右侧保留“写一条记录”主按钮。

### 3.2 统计信息

标题下方展示三个轻量统计卡：

1. 共同回忆：出游记录总数。
2. 一起到过的城市：从有效城市字段去重计算。
3. 胶囊倒计时：距离最近一颗未解锁胶囊的剩余天数；没有胶囊时显示“还没有胶囊”。

### 3.3 时间轴

- 记录按开始日期倒序排列，最近的记录在最上方。
- 每条记录显示日期范围、城市、标题和回忆描述。
- 有照片时显示封面图；没有照片时使用紧凑的纯文字卡片，不显示空白图片区。
- 有心情标签时显示标签；旧记录缺少标签时不显示占位标签。
- 照片数量大于零时显示“n 张照片”。
- 时间轴左侧使用细线和爱心节点连接各条记录。

### 3.4 删除按钮

- 原有文字“×”替换为圆形线框垃圾桶图标。
- 默认颜色保持低调，悬停或键盘聚焦时变为玫红色。
- 按钮提供明确的 `aria-label`，例如“删除厦门的出游记录”。
- 点击后先弹出包含记录标题的确认提示；只有再次确认才执行删除。

### 3.5 时光胶囊

- 时光胶囊融合在出游记录区域，不增加导航项。
- 电脑端放在时间轴右侧；手机端放在时间轴上方。
- 默认展示最近一颗未解锁胶囊。
- 解锁前只显示标题、创建日期、倒计时、文字数量状态和照片数量状态。
- 解锁前不得显示正文摘录、照片缩略图、模糊预览或其他可推测内容。
- 到达解锁日期后，按钮变为“共同开启”；打开后显示完整文字和照片。

## 4. 新版“写一条记录”表单

“写一条记录”使用独立表单，不复用“添加计划”的路线编辑界面。

### 4.1 必填字段

- 开始日期。
- 结束日期，且不得早于开始日期。
- 城市或地点。
- 记录标题。
- 回忆描述。

### 4.2 可选字段

- 心情标签：开心、第一次、浪漫、惊喜、治愈、难忘。
- 照片：支持选择多张图片。

### 4.3 表单布局

- 电脑端左侧填写，右侧实时预览保存后的时间轴卡片。
- 手机端改为单栏，预览显示在填写区域下方。
- 照片未上传时，预览自动切换为纯文字卡片。
- 保存按钮文案为“♡ 保存这段回忆”。
- 关闭或取消时，如果存在未保存内容，需要提醒用户确认放弃。

## 5. 时光胶囊创建与锁定规则

### 5.1 胶囊内容

- 标题，必填。
- 解锁日期，必填，必须晚于创建时间。
- 正文，必填。
- 照片，可选且支持多张。

### 5.2 24 小时修改期

- 胶囊创建成功后的 24 小时内可以修改标题、正文、照片和解锁日期。
- 修改期根据胶囊的 `created_at` 计算，不因页面刷新重新开始。
- 超过 24 小时后，内容彻底锁定，不能查看或修改。
- 锁定后仍可删除整颗胶囊，但必须二次确认。
- 到达 `unlock_date` 后，胶囊可以开启；开启后不再隐藏内容。

### 5.3 时间计算

- 创建时间保存为 UTC 时间戳。
- 解锁日期保存为稳定的 `YYYY-MM-DD` 日期字符串。
- 界面按用户本地时区显示日期和倒计时。
- 当本地日期达到解锁日期时视为可开启，避免纯日期受到时区小时偏移影响。

## 6. 数据模型与兼容

### 6.1 出游记录扩展

现有记录字段继续保留，并新增可选字段：

```text
city: string
moods: string[]
photos: PhotoReference[]
```

旧记录没有这些字段时：

- 城市优先从现有标题或地点字段读取；无法可靠解析时显示原内容，不进行猜测。
- `moods` 视为空数组。
- `photos` 视为空数组。
- 以纯文字时间轴卡片呈现。

### 6.2 胶囊数据

```text
id: string
title: string
body: string
photos: PhotoReference[]
created_at: UTC timestamp
updated_at: UTC timestamp
unlock_date: YYYY-MM-DD
opened_at: UTC timestamp | null
```

胶囊内容在客户端界面隐藏并不等同于加密。当前网站使用静态前端和现有云端数据体系，因此第一版承诺的是界面层锁定，而不是抵抗拥有数据库访问权限的人读取内容。页面文案不得将其描述为端到端加密。

## 7. 数据流

### 7.1 保存出游记录

1. 用户填写必填字段并选择可选标签、照片。
2. 前端验证日期和必填内容。
3. 照片先完成上传并得到引用。
4. 记录与照片引用一起写入现有云端数据体系。
5. 保存成功后关闭表单、刷新统计与时间轴，并滚动到新记录。

若照片上传成功但记录保存失败，需要保留表单内容并允许重试；不得让用户误以为整条记录已经保存。

### 7.2 保存与读取胶囊

1. 创建时保存完整内容、创建时间和解锁日期。
2. 渲染列表时先判断是否已经解锁。
3. 未解锁时只渲染允许公开的元数据，不把正文或照片 URL 放入可见 DOM。
4. 处于 24 小时修改期时显示“可修改至……”操作。
5. 超过修改期但未解锁时仅提供删除操作。
6. 到达解锁日期后显示“共同开启”，用户主动点击后展示内容并记录 `opened_at`。

## 8. 错误处理

- 云端读取失败：保留现有本地兜底逻辑并显示非阻塞提示。
- 记录保存失败：保持表单打开，保留所有文字、标签和已选择照片，显示重试按钮。
- 照片上传失败：明确标记失败图片，允许单张重试或移除，不阻止用户保存纯文字记录。
- 胶囊保存失败：不得进入“已封存”状态，保留全部填写内容。
- 删除失败：恢复卡片并提示失败原因，不提前从界面永久移除。
- 日期不合法：在对应字段附近显示错误，不只使用顶部通用提示。

## 9. 可访问性与响应式

- 所有图标按钮都有中文可访问名称。
- 垃圾桶按钮、标签按钮和保存按钮具备清晰的键盘聚焦样式。
- 确认弹窗可用键盘操作，焦点进入弹窗并在关闭后返回原按钮。
- 心情标签通过 `aria-pressed` 表达选中状态，不只依赖颜色。
- 图片提供可编辑或自动生成的替代文本；装饰图片使用空替代文本。
- 电脑端使用时间轴与胶囊双栏；小于 850px 时切换为单栏。
- 小于 570px 时表单、统计卡和记录卡进一步简化，避免横向滚动。

## 10. 测试与验收

### 10.1 数据与逻辑测试

- 新记录按日期正确排序。
- 结束日期早于开始日期时无法保存。
- 旧记录缺少新增字段时仍能渲染。
- 城市统计正确去重，并忽略空值。
- 胶囊创建后 24 小时内可编辑，超过边界后不可编辑。
- 解锁日期之前不渲染正文和照片；到达日期后可开启。
- 删除必须经过确认，取消确认不会改变数据。

### 10.2 交互测试

- 表单关闭前正确提醒未保存内容。
- 图片上传单张失败不影响其他图片。
- 云端失败后表单内容不丢失。
- 电脑端和手机端都能完成新增记录与创建胶囊流程。
- 键盘可以完成标签选择、保存、取消和删除确认。

### 10.3 视觉验收

- 出游记录区域不再出现大面积无意义留白。
- 有图与无图记录都保持统一的视觉层级。
- 删除按钮默认低调，悬停和聚焦时状态清晰。
- 胶囊与时间轴属于同一视觉系统，不产生新的导航负担。
- 公开页面加载旧数据后布局稳定，没有内容跳动或重叠。

## 11. 实施边界

本设计可以作为一个实现计划完成，包含以下四个紧密相关部分：

1. 出游记录区域与时间轴样式。
2. 新版记录表单及可选照片、标签。
3. 时光胶囊数据与 24 小时锁定规则。
4. 旧数据兼容、错误处理与测试。

实现阶段不得顺带修改出游计划、地图、交通图标、纪念日或想做的事区域。
