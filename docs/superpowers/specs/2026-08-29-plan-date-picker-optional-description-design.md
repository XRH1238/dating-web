# 出游计划日期选择器与可选描述设计

**日期：** 2026-08-29  
**状态：** 用户已选择方案 1，等待书面规格复核

## 目标

完成两个局部体验调整：

1. “添加出游计划”的开始、结束日期改用与“写一条出游记录”相同的中文日期选择界面。
2. “简短描述”改为选填，空内容也可以保存计划。

## 范围

本次修改：

- 出游计划表单的日期摘要按钮、年月日手动输入和内嵌月历；
- 出游计划日期选择、校验、重置和提交逻辑；
- 简短描述的表单约束与空描述展示；
- 对应自动化测试和缓存版本参数。

本次不修改：

- 出游记录日期选择器的行为；
- 计划日期和描述的数据库字段或存储格式；
- 时间胶囊日期控件、路线编辑器、地图逻辑；
- Supabase 配置、云端数据或 GitHub Pages 发布状态。

## 日期选择界面

- 计划表单使用与记录表单一致的 `record-date-picker` 视觉类，保持摘要按钮、手动年月日输入、月历、选中态、焦点态和窄屏布局一致。
- 计划日期控件使用计划专属 ID 和 `data-plan-*` 属性，避免与记录日期控件互相影响。
- 开始日期与结束日期各自保存独立选择状态，并可通过摘要按钮切换当前编辑目标。
- 点击月历日期或完整填写年月日后，同步更新隐藏的 `start_date` 和 `end_date` 字段。
- 上一月、下一月操作只改变计划月历视图。
- 打开“添加出游计划”时重置计划日期状态；关闭后不影响出游记录草稿。

## 日期校验与数据兼容

- 开始日期、结束日期继续为必填。
- 日期缺失、日期不存在或结束日期早于开始日期时阻止提交，并在计划日期控件内显示中文提示。
- 校验失败时不清空标题、路线或描述。
- 提交时继续调用 `MapLabelLayout.serializeDateRange(start, end)`，保存格式仍为 `YYYY-MM-DD/YYYY-MM-DD`。
- 已有计划、本机缓存、Supabase 数据和列表日期格式化保持兼容。

## 可选描述

- 移除“简短描述”文本域的 `required` 约束。
- 提交时继续去除首尾空白；空值保存为 `""`。
- 计划卡片有描述时正常显示；描述为空时不输出空的 `<p>`，避免多余间距。
- 已有非空描述不发生变化。

## 实现边界

- 日期计算继续复用 `record-date-picker.js`，不复制日期合法性、月份移动或月历网格算法。
- 记录日期现有状态和事件函数保持不变；计划增加独立状态和事件入口，以降低回归风险。
- 日期选择界面复用现有 CSS，不引入新的视觉体系或第三方组件。

## 可访问性与响应式

- 日期摘要和月历日期均为键盘可聚焦按钮。
- 当前编辑目标使用 `aria-pressed`，已选择日期使用 `aria-selected`。
- 年、月、日输入保留明确的中文 `aria-label` 和数字输入模式。
- 状态区域使用 `role="status"` 与 `aria-live="polite"`。
- 768px 以下继续使用现有日期控件的单列摘要和可换行年月日布局。

## 测试与验收

- 先添加失败测试，证明计划表单不再使用原生 `type="date"`，而是拥有独立隐藏字段和完整日期选择器结构。
- 测试计划日期的独立状态、手动输入、月历选日、前后翻月与提交前校验。
- 测试描述文本域不再必填，空描述提交被接受，空计划卡不渲染描述段落。
- 运行完整 Node 测试套件，确保出游记录日期和其他功能没有回归。
- 在本地网站打开添加计划面板，分别检查桌面和窄屏布局。

## 成功标准

- 添加计划与添加记录呈现相同类型的日期选择界面。
- 两个表单的日期状态互不干扰。
- 开始、结束日期仍必须完整有效，结束日期不能早于开始日期。
- 简短描述为空时可以保存，列表中没有空白描述占位。
- 数据格式与已有数据保持兼容，完整自动化测试通过。
