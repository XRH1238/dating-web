# 出游日期范围与路线地图刷新设计

## 目标

出游计划和出游记录统一使用开始日期与结束日期，避免用户自由输入造成格式不一致。保存出游计划后，地图应立即显示所有能够识别的路线；路线城市输入可以使用常用简称或正式全称，地图和页面统一显示正式行政区全称。

## 范围

本次调整包括共享添加面板的日期输入、计划和记录的日期显示、旧数据兼容、路线城市名称规范化、城市坐标来源及计划保存后的地图刷新。照片城市输入与照片挂图沿用同一城市解析能力，但不改变照片上传流程。Supabase 表结构不迁移，地图边界、缩放、拖拽和标签碰撞交互保持不变。

## 日期范围设计

### 表单

- 出游计划和出游记录共用的添加面板显示“开始日期”和“结束日期”两个原生 `date` 输入框。
- 两个日期都为必填项。
- 结束日期不得早于开始日期；选择开始日期后，结束日期的最小可选日期同步更新为该日期。
- 单日行程允许开始日期与结束日期相同。
- 表单切换计划与记录类型时沿用同一套日期规则。

### 存储与兼容

- 不新增 Supabase 字段，继续使用现有 `date` 字段。
- 新数据以 `YYYY-MM-DD/YYYY-MM-DD` 存入 `date` 字段，例如 `2026-08-06/2026-08-08`。
- 读取时通过独立的日期范围解析函数处理新旧数据，不在各个渲染函数中重复拆分字符串。
- 旧数据如果只有一个可识别日期，则按单日行程处理，即开始日期与结束日期相同。
- 旧数据无法被可靠解析时保留原文字显示，不阻止其他内容渲染，也不自动改写远端数据。

### 显示

- 多日行程统一显示为 `2026.08.06 — 2026.08.08`。
- 单日行程统一显示为 `2026.08.06`，不重复显示两个相同日期。
- 出游计划卡片和出游记录时间轴调用同一个格式化函数，保证格式一致。

## 行政区名称与路线定位

### 城市索引

- 从审核后的地图行政区数据构建城市索引，不再以当前约 40 个城市的硬编码坐标表作为主要来源。
- 城市索引只包含有效地级行政区和四个直辖市；保护区、马场、林场、县级市、县、自治县及其他非地级行政区不得进入索引。
- 每个索引项包含正式全称、可接受的简称、行政区划编码及用于路线绘制的地图坐标。
- 坐标从对应行政区几何计算，确保所有 333 个地级行政区和 4 个直辖市都可以用于路线定位。

### 名称解析

- 输入“厦门”或“厦门市”都解析为正式名称“厦门市”；输入“北京”或“北京市”都解析为“北京市”。
- 自治州、地区和盟同时接受数据中的旧缺失后缀形式及完整正式名称，但保存、图例、路线节点和标签一律显示完整正式名称。
- 名称解析先执行去首尾空格和正式名称精确匹配，再执行已登记简称匹配；不做模糊猜测，避免把同名县级单位误配为地级单位。
- 无法识别的名称不绘制路线，并在地图图例的“未定位”区域显示用户原始输入，便于修改。

## 地图刷新修复

- `renderChinaMap` 会替换地图容器内容，因此初始 HTML 中的 `#map-overlay` 会在第一次地图渲染后消失。
- `renderFootprintMap` 不再把已经不参与路线绘制的 `#map-overlay` 当作必需节点，也不因该节点缺失提前返回。
- 地图 SVG 和图例是渲染所需的节点；计划保存、远端数据加载、删除计划和页面初始渲染都继续通过 `renderAll` 触发路线重算。
- 每次路线重算先把输入名称解析为正式名称，再查找坐标和生成路线，以保证简称与全称得到同一结果。
- 路线所涉及的城市继续进入地图标签优先集合，使其在标签碰撞布局中优先显示。

## 组件边界

- 日期范围解析与格式化函数负责表单值、存储字符串、旧数据兼容及展示文本转换。
- 行政区索引构建函数负责筛选有效行政区、补全正式名称、生成别名和计算坐标。
- 城市解析函数只接收用户输入并返回索引项或“未识别”，不直接操作 DOM。
- 表单提交负责校验日期、规范化路线分段并调用现有保存函数。
- 地图渲染负责使用已经解析的路线数据绘图和更新图例，不承担行政区真伪判断。

## 错误处理

- 结束日期早于开始日期时阻止提交，在日期输入附近显示明确提示，并把焦点移到结束日期。
- 行政区数据未加载时保留现有地图数据加载失败提示；页面的计划和记录列表仍可使用。
- 某一段路线包含未知城市时只跳过该段，其他有效路线仍正常绘制。
- 若旧日期文本无法解析，则原样转义后显示，防止数据丢失或页面报错。

## 验证标准

- 单元测试覆盖日期范围解析、单日与多日格式、结束日期校验以及旧单日期文本兼容。
- 表单集成测试覆盖计划和记录都使用两个 `date` 输入框，并以统一格式保存与显示。
- 行政区索引测试覆盖 333 个地级行政区与 4 个直辖市、正式全称唯一、简称与全称解析一致以及非行政区被排除。
- 路线测试覆盖硬编码表之外的地级行政区也能定位、未知城市只跳过相应分段以及路线名称使用正式全称。
- 回归测试断言 `renderFootprintMap` 不依赖 `#map-overlay`，保存计划和远端计划加载后都生成路线元素并更新图例。
- 在内置浏览器中分别新增单日计划、多日计划和多日记录，确认日期格式统一；使用简称与全称各新增一条路线，确认地图立即出现路线并显示正式全称。
