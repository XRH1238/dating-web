# 可编辑出游记录与高质量图片压缩设计

## 目标

让已保存的出游记录可以再次编辑，包括日期、城市、标题、正文、心情和照片；同时缩小后续普通照片的云端占用，并保留现有高清查看、缩放和拖动体验。

## 已选方案

### 记录编辑

复用现有“写一条出游记录”侧面板，不新增第二套表单。每张记录卡片在删除按钮旁增加“编辑”按钮。打开编辑后：

- 表单标题和提交按钮切换为“编辑出游记录”和“保存修改”。
- 开始日期、结束日期、城市、标题、正文和心情自动回填。
- 现有照片和新选择的照片一起显示在预览区。
- 每张预览图提供移除按钮；移除只改变编辑草稿，保存成功前不删除云端文件。
- 媒体总数继续采用现有上限：每条记录最多 20 个照片、视频或实况照片项目。达到上限时，需要先移除一个项目再添加。
- 关闭编辑面板不会改动已发布记录；再次从记录卡片进入编辑时重新读取已保存数据。

这比卡片内直接编辑更适合日期选择器、心情选择和照片管理，也能复用已经验证过的表单校验。独立编辑页面会增加导航和状态同步，因此不采用。

### 保存与文件一致性

保存编辑时按以下顺序处理：

1. 校验日期、必填文字和媒体总数。
2. 压缩并上传本次新增的普通照片；视频和实况照片保持原文件。
3. 更新 `love_records` 中的文字字段、心情和最终照片列表。
4. 记录更新成功后，删除用户在本次编辑中移除的 Storage 文件；实况照片同时删除静态图和 MOV。

如果新增文件上传后数据库更新失败，立即清理本次新增文件，旧记录保持不变，表单继续打开并显示错误。若数据库更新成功但旧文件清理失败，记录仍保存成功并提示“部分旧文件未清理”，避免让用户误以为修改丢失。

离线或网络异常时不覆盖云端旧记录，也不清空表单。编辑成功后才退出编辑模式。新建记录仍沿用已有的本机草稿与待同步逻辑。

## 图片压缩

新增独立的浏览器端图片压缩模块，供相册、出游记录和时间胶囊三个上传入口共同使用：

- 只处理普通静态照片；视频、实况照片的静态图和 MOV 均保持原文件。
- 最长边超过 3200px 时等比例缩小到 3200px；不放大小图。
- 对适合压缩的普通大图以约 88% 质量导出 WebP；保留透明通道。
- 压缩结果没有比原文件更小时继续使用原文件。
- 浏览器无法解码或压缩某种格式时回退上传原文件，并给出非阻断提示。
- 已上传的 31 张照片不重新处理、不改 URL。

文件名、MIME 类型和预览引用随压缩结果更新，防止扩展名与实际格式不一致。压缩在上传前发生，因此失败不会产生半个云端对象。

## UI 与反馈

- 记录卡片操作区包含“编辑”和“删除”，两者都有可访问名称。
- 编辑预览区区分“已保存”和“待上传”媒体，并允许分别移除。
- 选择照片后显示原始总大小；压缩完成后显示实际上传大小和节省比例。
- 保存期间禁用提交按钮，防止重复上传和重复更新。
- 所有错误写入现有表单状态区域，不使用会丢失上下文的页面跳转。

## 数据与兼容性

数据库无需迁移，继续使用 `love_records.photos` JSON 数组。前端新增编辑状态保存记录 ID、现有照片、新增草稿媒体和待删除照片。Storage 客户端新增按路径删除文件的方法。

旧记录、旧照片和待同步的新建记录保持兼容。记录编辑优先匹配数据库 ID，不依赖当前排序后的卡片索引，避免时间轴重新排序后修改错记录。

## 测试与验收

- 单元测试覆盖压缩尺寸计算、不放大小图、格式回退和“结果变大则保留原图”。
- 集成测试覆盖编辑按钮、字段回填、已有照片保留/移除、新照片追加、20 项总上限和按 ID 更新。
- 数据一致性测试覆盖“数据库成功后才删旧文件”和“更新失败时清理新上传文件”。
- 回归运行现有全部测试，确认新建记录、实况照片和高清查看器未受影响。
- 在本地页面实际编辑一条测试态记录，检查桌面与窄屏布局；不向真实后端写入测试数据。
- 推送后检查 GitHub Pages 资源版本和线上记录编辑入口，并复查照片缩放、缩小和拖动。
