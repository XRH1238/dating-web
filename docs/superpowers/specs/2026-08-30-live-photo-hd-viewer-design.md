# 实况照片与高清查看器设计

## 目标

在现有照片墙、出游记录和时间胶囊中增加统一的高清媒体查看器，并支持 Apple 实况照片。普通照片点击后进入全屏原图查看；实况照片在全屏查看器中长按画面或点击 `LIVE` 播放。首页主视觉图片不在本次范围内，待用户提供新图片后单独替换。

## 已确认体验

- 采用方案 B：点击照片进入高清全屏查看器。
- 实况照片显示 `LIVE` 标记；长按画面或点击 `LIVE` 播放，松开或播放结束后回到静态照片。
- Mac 使用按钮和鼠标操作；iPhone Safari 支持触摸与长按。
- 查看器支持关闭、上一张、下一张、键盘方向键和 `Escape`。
- 提供放大、缩小和复位控件；触控板/鼠标滚轮可缩放，图片始终使用原始资源而非缩略压缩版本。
- 尊重 `prefers-reduced-motion`，减少非必要过渡动画，但不禁用用户主动触发的实况播放。

## 技术路线

采用混合播放器：

1. 对照片与配套视频完整、Apple 播放器可正常初始化的资源，优先使用 Apple LivePhotosKit JS。
2. LivePhotosKit 加载失败、Apple CDN 不可用或播放器触发资源错误时，自动回退到网站自带的图片叠加视频播放器。
3. 只有静态照片时，按普通高清照片显示；网站不会把普通照片误报为实况照片。

Apple 官方说明 Live Photo 由一张静态照片和一个视频资源组成，网页播放器需要同时设置 `photoSrc` 与 `videoSrc`。官方脚本地址为 `https://cdn.apple-livephotoskit.com/lpk/1/livephotoskit.js`。脚本仅在首次查看实况照片时延迟加载，普通照片页面不会请求 Apple CDN。

## Safari 上传限制

macOS Photos 通过“导出未修改的原片”可以得到同名 JPG/HEIC 与 MOV 文件。网站会按不区分大小写的文件主名自动配对，例如 `IMG_1234.HEIC` 与 `IMG_1234.MOV`。

iPhone Safari 从照片选择器上传时不保证同时交付这两个资源。网页无法从一张普通静态文件可靠判断它原本是否属于实况照片。因此：

- 上传区明确提示：“实况照片请同时选择原图和同名 MOV 文件”。
- 同一批次中同名的图片和 MOV 自动组成一个实况媒体项，并只占 20 个媒体上限中的 1 个。
- 未匹配文件继续作为普通照片或普通视频，不进行可能错误的猜测配对。
- 状态区报告成功配对数量与未匹配 MOV 数量。

## 模块边界

### `live-photo.js`

新增无 DOM 依赖的媒体归类模块，负责：

- 根据 MIME 和扩展名识别图片、视频以及 HEIC/HEIF/MOV。
- 生成用于匹配的标准化文件主名。
- 将同一批次文件整理为普通图片、普通视频或实况照片对象。
- 计算逻辑媒体数量、拒绝数量、超限数量和未匹配 MOV 数量。
- 兼容旧媒体对象，缺少新字段时一律按普通媒体处理。

### `media-viewer.js`

新增查看器控制模块，负责：

- 打开、关闭和切换当前媒体。
- 普通图片的原图显示与缩放状态。
- 延迟加载 LivePhotosKit，并监听 `canplay`、`error`、`ended`。
- LivePhotosKit 失败时切换到原生 `<video>` 回退播放器。
- 键盘、鼠标、触控与焦点恢复。

### `script.js`

保留业务数据和上传职责：

- 三个上传入口统一调用媒体归类模块。
- 上传实况照片的静态资源和视频资源，并生成统一媒体引用。
- 渲染媒体触发按钮和 `LIVE` 标记。
- 将当前页面中可查看的媒体集合交给查看器。

### `index.html` 与 `styles.css`

新增语义化 `<dialog>` 查看器、状态提示、缩放与切换按钮。样式沿用现有玫瑰色设计变量，桌面端居中显示，手机端占满安全视口，不产生横向滚动。

## 数据结构

统一媒体引用保持向后兼容：

```js
{
  kind: "live-photo",       // 旧数据无此字段时按普通媒体处理
  name: "IMG_1234.HEIC",
  type: "image/heic",
  path: "records/...",
  url: "https://...",       // 高清静态照片
  motion_name: "IMG_1234.MOV",
  motion_type: "video/quicktime",
  motion_path: "records/...",
  motion_url: "https://..." // 实况视频
}
```

`love_records.photos` 与 `love_capsules.photos` 已是 JSONB，无需数据库结构迁移。`love_photos` 目前为固定列，需要增加以下可空字段：

- `type text`
- `media_kind text`
- `motion_name text`
- `motion_type text`
- `motion_path text`
- `motion_url text`

新增本地 SQL 迁移文件。迁移未执行时，普通照片仍可使用；实况照片上传必须停止并显示“云端尚未启用实况照片字段”，不能静默丢弃配套视频。

## 上传与画质

- 不调整尺寸、不重新编码、不转成低质量 JPEG，不对原始照片或 MOV 做有损压缩。
- 云端上传静态资源和视频资源原文件。
- 列表继续使用懒加载，查看器打开时加载当前原图并预取相邻一张。
- 本地离线模式仍使用 Data URL；实况文件可能超过浏览器本地存储容量，失败时保留表单并提示联网后重试，不宣称保存成功。
- 单个实况照片按一个媒体项计数，但上传体积等于照片与视频之和。

## 错误与回退

- Apple CDN 加载失败：自动使用原生视频回退，不影响静态照片查看。
- Apple 播放器报告图片或视频错误：记录当前会话失败并回退，避免重复闪烁。
- 配套视频缺失：显示普通高清照片，不显示 `LIVE`。
- 配套照片缺失：按普通视频处理。
- 云端第二个文件上传失败：不写入不完整实况引用；保留草稿并提示重试。
- 旧数据、空 URL 或损坏资源：查看器显示可恢复错误并允许切换下一张。

## 安全与隐私

- 文件名和 URL 进入 HTML 前继续执行转义，不把媒体对象直接拼成未经转义的 JSON 属性。
- LivePhotosKit 从 Apple CDN 延迟加载时，Apple 会接收到正常网络请求信息；只有用户主动打开实况照片时才加载。
- 不上传 EXIF 到额外分析服务，不增加第三方图片处理服务。

## 无障碍与响应式

- 缩略图触发器使用按钮语义并提供“查看高清照片”或“查看实况照片”名称。
- `<dialog>` 打开后焦点进入关闭按钮，关闭后回到原触发器。
- `Escape` 关闭，左右方向键切换，`+`/`-` 缩放。
- 手机端按钮满足触摸尺寸，适配安全区域；视频默认不自动带声音播放，用户主动触发后按浏览器策略播放。

## 测试策略

先写失败测试，再实现：

1. 媒体归类单元测试：同名 HEIC/JPG + MOV 配对、普通文件、空 MIME、大小写、限制计数、未匹配文件。
2. 上传集成测试：三处入口共享归类、双资源上传、失败时不产生半条记录、旧数据兼容。
3. 查看器集成测试：dialog 标记、高清原图、`LIVE` 控件、延迟加载 Apple 脚本、错误回退、键盘入口。
4. 样式测试：全屏、`object-fit: contain`、缩放、移动端安全区、焦点状态和减少动态偏好。
5. 运行全部 Node 测试与 `git diff --check`。
6. 在 Codex 内置浏览器中验证普通照片、模拟实况照片、失败回退、桌面与手机宽度。

## 不在本次范围

- 更换首页主视觉图片。
- 在浏览器内重新编码或生成 Apple 配对元数据。
- 将旧的普通照片自动推断为实况照片。
- 对现有媒体做批量迁移或删除。
